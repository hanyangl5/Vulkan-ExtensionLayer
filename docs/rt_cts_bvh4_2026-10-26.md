## Production data flow

1. Size queries use the shared header/node/leaf/parent layout with checked 64-bit
   region arithmetic. Tests compare the production plan against the common
   reference planner, including >4 GiB layouts and the mandatory primitive-count
   size case. This is arithmetic evidence, not a giant GPU allocation test.
2. Application scratch contains Mesa build state/IR, encoder mapping, full
   geometry flags and status. A small compute preparation pass writes final
   header offsets and side tables; the imported leaf/Morton/LBVH/bounds passes
   produce construction IR there.
3. The common three-phase GPU encoder writes final BVH4 directly to AS backing
   storage. The TLAS leaf variant reads already-built runtime BLAS bounds;
   explicit identity relocation retains those runtime BDAs in instance records.
   There is no old-format detection, retained IR pointer or CPU topology/count
   readback in this production path.
4. Encoder errors atomically mark the runtime header invalid as well as its
   scratch status. Traversal checks identity/version/type/invalid status before
   following the root, so it does not need construction scratch afterward.
5. Traversal uses 64-bit region/index arithmetic and original IDs/full flags.
   Separate TLAS/BLAS cursors survive candidate suspension. A constant-space
   parent walk scans all four child slots and can ascend every internal ancestor;
   it does not drop children when a fixed stack fills.

The common GPU encoder currently emits binary arity in the four-child node
format; the CPU reference can collapse four children, and traversal handles
all four. Four-child GPU collapse remains open. A bounded fast traversal path
can be added ahead of the constant-space path. Mesa construction IDs are still
32-bit byte offsets; execution explicitly retains that construction ceiling,
even though runtime address/size arithmetic is 64-bit. Large construction IDs,
refit, broader builder variants and ill-conditioned transform qualification
remain mandatory follow-up work.

## Actual typed source-CFG component

The standalone RTP suite passes 13/13; validation-enabled continuation analysis,
frame-codec and actual source-CFG execution pass 3/3. Logs and hashes are in the
JSON. The new compiler consumes validated source SPIR-V, selects the requested
entry, inlines reachable helpers and generates resumable compute states from
actual basic blocks and post-ReportIntersection sites. It retains source ALU,
composites, ext-inst operations, branches/switches and parallel Phi-edge copies.
Function-local storage persists in frame backing; only suspension-live SSA is
spilled, and the report bool is injected after completion.

The independent GPU/CPU oracle checks 32 invocations and 372 report completions,
including dynamic loop swaps, two report sites, a suspending helper, aggregate
copies, local aliases, source SSBO I/O/late poisoning, push constants and launch
IDs. Blocked and terminal redispatches preserve memory. Overflow/capacity guards
reject excess dispatch IDs and undersized frame descriptors before frame access.
Regressions retain FP controls, quoted literals and copied-pointer NonUniform.

This is actual source CFG lowering, but it is not wired into pipeline creation.
TraceRay/Callable, payload/attribute/invocation ABI, unsupported provenance and
memory operands, unresolved specialization, subgroup/derivative semantics and
non-Logical/GLSL450 memory models fail explicitly. Frame binding collisions are
rejected. Completion currently requires synchronized dispatches with no concurrent
frame writes. These boundaries do not complete M0/M3 or resolve legacy RTP CTS.

## Open address-alignment proof

A focused ordinary-buffer probe found a concrete missing prerequisite. For the
exact translated STORAGE_BUFFER|SHADER_DEVICE_ADDRESS usage, RTX3080 reports
alignment16. Binding at the legal offset16 yields `0x6fe0010`, whose remainder
modulo128 and modulo256 is16. The current GetASAddress implementation returns
backing BDA + AS offset, so it lacks the required 256-byte public AS alignment;
the shared encoder also rejects that BLAS reference. This AS failure is inferred
from production code plus the resource probe, not presented as an executed AS
CTS failure.

The [AS address specification](https://docs.vulkan.org/refpages/latest/refpages/source/vkGetAccelerationStructureDeviceAddressKHR.html)
also requires GENERIC AS addresses in one buffer to preserve creation-offset
differences. Independent per-AS aligned tokens alone would not satisfy that
case. The next M0/M4 work must prove an aligned address/context mechanism,
GENERIC offsets, scalable resource transport and suballocated-buffer behavior.
The passing CTS selections above do not close this gap.

The manual probe is committed as `layers/raytracing/tests/probe_bda_alignment.c` and
built as `probe_bda_alignment`; its captured validation-enabled output and
source hashes are in the JSON. It makes no native AS calls. Run it without a
fallback layer; observed buffer alignment is device-specific.
